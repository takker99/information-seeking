# Wiki Write (Ingest / File-back)

外部ソースのingest、またはQuery回答・対話で生まれた知見のfile-backによって、`wiki/`のページを作成・更新し知識ネットワークに編み込む操作。
ディレクトリ構成・命名・機械要件は`AGENTS.md`に従う。

## 手順

1. 入力を用意する
   - Ingest時: 対象ソースを読む。PDF等の非テキストソースは、まずテキスト抽出して読む。図表が重要と判断したページのみ、当該ページと前後数ページを画像化して読む
   - File-back時: 人間が承諾したQuery回答や対話の知見を入力として手順2へ進む
2. 既存ページとの接続点・文脈・スタイルを把握する
   - `wiki/index.md`と`bash .agents/scripts/search-pages.sh "<検索語>"`で既存ページとの接続点と未カバー領域を特定する
   - 更新候補の既存ページと、新規作成予定の概念名に言及している既存ページを`bash .agents/scripts/read-page.sh "<タイトル>"`で読む。新規作成のつもりでも、すでに複数ページから未作成リンクとして言及されている文脈がないか確かめる
   - 新しくページを作るディレクトリの直近のページや近いテーマの既存ページを1〜2枚読み、見出しの立て方、frontmatterの項目、記述の粒度を観察して合わせる
3. 要点と編み込み計画を人間と議論する
   - Ingest時: ソースの要点3〜5個と、どの既存ページを更新し何を新規ページとして切り出すかの編み込み計画を提示し、何を重視するか聞く
   - File-back時: 提案時に作成・更新対象が合意済みであればそのまま手順4へ進む
4. ページを作成・更新する
   - Ingest時は`wiki/sources/YYYY-MM-DD タイトル.md`を作成する。要約、関連する`concepts/`・`entities/`へのリンク、情報源へのポインタを含める。既存の過去`sources/`ページは当該ソース時点の要約として維持する
   - 新規の`concepts/`・`entities/`・`analyses/`ページを作成し、関連する既存ページと相互に`[[wikilink]]`を張る
   - 影響を受ける既存の`concepts/`・`entities/`・`analyses/`ページを更新する。既存の主張と矛盾する場合は「⚠ Contradiction: [旧主張] vs [新ソース]」の形式で明示する。複数ソース間の比較や矛盾の分析が長くなる場合は`analyses/`にページを切り出してよい
5. リンク接続を確認し、台帳を更新する
   - 追加・変更したリンク表記が接続先の既存ページタイトルと一致しているか確かめる。表記ゆれで繋がっていない箇所があれば修正する
   - `wiki/index.md`を更新し、新ページの追加と変更された要約の反映を行う
   - `wiki/log.md`に`ingest`または`file-back`のエントリを追記し、本文に触れたページ数の内訳を記録する
   - logは追記専用。コミット前に見出しの件数（`grep -c '^## '`）で欠損がないことを確認する
   - `bash .agents/skills/llm-wiki-lint/scripts/lint.sh`を実行し、孤立ページ、オープンリンク（未作成ページへのリンク）、`index.md`の漏れがないか機械検証する。オープンリンクは欠陥ではないので、表記・パス形式の確認だけ行い、意図的なものは残す

## 内部リンクの選定基準

リンク記法`[[タイトル]]`はナレッジグラフへの接続として選ぶ。
主張単位の出典引用は`[[ソースページ]] p.XX`（claim粒度引用）の形を基本にする。ページ番号なしの同じソースへの裸の反復は重複リンクとして扱う。

- 採用するリンク
  - ページの主題を構成する中心概念であり、既存ページまたは複数ページが共有する未作成概念に繋がる語。ソース内の同義語や表記ゆれが既存ページを指す場合は、本文中の初出箇所で既存ページタイトルに表記を揃えてリンクする
  - 将来複数のソースや議論が接続する明確な未解決概念
- 却下するリンク
  - ページの主題を構成しない周辺的な固有名詞や一般語
  - 主題と直接関係のない、被リンク数が突出したハブページへのリンク
  - 文字列は一致するが文脈が異なるページへのリンク
  - 一覧・点呼内に列挙される他項目名（主題を構成しない点呼）。substantiveな記述が付く場合は、その主張の初出箇所で接続する
  - 同一ページ内で既にリンク済みの重複リンク（関連節での再掲を含む。ただし `[[ソース]] p.XX` のように引用箇所が異なるclaim粒度引用の反復は重複に数えない）

同一ページ内の同じページへのリンクは初出1回だけ。2回目以降は平文にする（引用箇所が異なるclaim粒度引用は例外）。見出し内にはリンクを置かず、見出しの主題は直後の本文初出でリンクする。表セル内のリンクは、その表の主題に必要な場合のみ1セル1つまでにする。

- 関連節（関連ページの列挙節）は本文で未リンクのページのみを列挙する。該当が無ければ節ごと削除してよい

重複を解消する時は主張を担う初出の[[リンク]]を残す。列挙行・関連節・参考文献行の再掲は`[[ ]]`を外して平文化してよい（役割注記の文言は保持）。同一箇所の重複引用は2つ目を外すか『同 p.XX』に縮約する（直前の引用と別ソースの文脈では縮約しない）。

関連節・列挙行・出典節のエントリを削除する時は、本文に同内容のリンクが既にあるなら削除し、無いなら要約文とリンクを本文に移してから削除する。『同 p.XX』は直前の引用が同一ソースで、間に別ソースの引用を挟まない場合のみ使う。

## 系譜・判別のパターン

- 訂正は必ず旧→新の系譜をページ内に残す。撤回・改算の経緯を含めて消さない
- 正本と記録を分ける時、正本側に役割NOTEを置き、記録→正本は根拠の引きで参照する（正本→記録は履歴を辿る用途）
- ラベル・系列の混在は数値差し替えでなく判別NOTEを置く（差し替えは管理側の別作業として指し示す）
- 年度・時点で変わる値は、いつの値かを本文に明記する。過年度値は当時の値として保持し、最新値と同じ表に混在させない（必要なら年度列を分ける）

## 新規ページの作成

新規ページは2+ページからの言及、または複数ページが共有する未作成概念で作る。entityを散在する言及から新規作成する時は:

- 点呼的な言及ではなく、substantiveな記述（仕様・数値・手順等の内容が付くもの）だけを集約する
- 1ページのみのtranscriptにしか無い分析主張は、sourcesページを経由しない限り持ち込まない
- 年度別・時点別にシリーズ更新される表は1枚の正本ページに一元し、他ページは見出しの1数値と正本への委譲リンクにする

## sourcesページのfrontmatter形式

```yaml
---
raw: "raw/ファイル名.md"
source_url: "https://..."
accessed: YYYY-MM-DD
---
```

情報源へのポインタとして`raw:`または`source_url:`を1つ以上含める。両方ある場合は両方書く。どちらも書けないソースはingestしない。

- `raw:` — `raw/`からのファイルパスを書く
- `source_url:` — URL参照ソースのURLを書く。リポジトリの場合は検証できるよう`commit:`に参照時のcommit hashを固定して併記する
- `accessed:` — 外部URL等を参照・取得した日を書く任意項目

analyses/ で外部URLを出典にする場合は、frontmatterに `source_url:`（と任意で `accessed:`）を書いてよい。`sources:` は入力raw・スクリプトのreproducibility manifestであり、外部URLの出典とは別の意味を持つ。
